# 阅读指南

这是一本**工程手册**，不是概念综述。每一章都按同一个节奏展开：先讲人话，再上结构，然后给代码，最后给避坑清单。

## 01 这本手册适合谁 {#who}

| 角色 | 你能拿到什么 |
| --- | --- |
| 零基础 / 产品 | 判断「这个能力该做成技能还是写死」，和工程师说同一种语言 |
| AI 应用开发者 | 一周内做出可注册、可调用的最小技能中心 |
| 后端 / 平台工程师 | 把技能做成服务：注册、版本、权限、沙箱、计费、审计 |
| 架构师 / SaaS 创业者 | 完整的六层架构图、选型矩阵与上线路线图 |

::: tip 人话翻译
这本书解决的不是「怎么让模型更聪明」，而是「怎么让一个团队的能力被重复使用，还不失控」。
:::

## 02 全书的写法 {#style}

每一节都尽量长这样：

1. **生活化类比**：先让你有画面感（技能中心 = 应用商店 / 工具超市）。
2. **图解**：一张结构图或时序图，把角色和顺序钉死。
3. **对比表**：把「该做 / 不该做」摊开。
4. **可运行代码**：最小能跑的版本，而不是伪代码。
5. **避坑清单**：别人踩过的坑，你少踩一次就赚一次。
6. **参考来源**：能点开官方原文的地方，绝不让你只看我们的转述。

## 03 章节依赖关系 {#graph}

<Diagram id="book-map" />

三条主线的依赖关系：

- **概念线（00 → 01 → 03）**：先分清 Tool / Skill / MCP / Agent，再谈元数据。概念不清，元数据一定设计错。
- **工程线（02 → 05 → 06 → 11）**：架构分层决定模式选择，模式决定安全边界，安全边界决定部署形态。
- **运营线（04 → 07 → 14）**：生命周期、发现、性能，本质上都是「技能变多之后」的问题。

## 04 三条推荐路径 {#paths}

### 零基础 / 产品同学

```text
00 开篇 → 01 概念 → 03 元数据 → 06 安全 → 10 选型
```

不写代码也能读完。重点是能判断：哪些能力值得做成技能、哪些风险必须有人管。

### 开发者

```text
13 Demo（先跑起来） → 02 架构 → 05 模式 → 03 元数据 → 12 踩坑
```

先把最小 Hub 跑通，你再看架构和模式，会有「原来是这么回事」的感觉。

### 架构师

```text
02 架构 → 06 安全 → 10 选型 → 11 部署 → 09 生态
```

先定边界和成本，再谈实现。技能中心最容易死在对组织能力的高估上。

## 05 约定与符号 {#conventions}

| 写法 | 含义 |
| --- | --- |
| `skill.name@1.4.0` | 技能名 + 语义化版本，本文档统一用 `@` 固定版本 |
| `scope` | 权限范围，例如 `orders:read`、`refund:write` |
| `tenant` | 租户标识，所有查询必须带，禁止从入参信任 |
| `trace_id` | 一次调用链的标识，审计、观测、计费共用 |
| 【人话翻译】 | 用大白话解释上一段工程描述 |

::: warning 关于版本号
书里的版本号是示例，不代表任何真实服务。生产环境请用你自己的注册表，并且**永远固定版本**，不要让 Agent 用 `latest`。
:::

## 06 你可以怎么用这本书 {#use}

- **自学**：按路径读，每章末尾的 Demo 都自己跑一遍。
- **团队分享**：每章开头都有一个「一句话结论」，适合直接做分享标题。
- **方案评审**：第 02、06、10、11 章可以直接当评审 checklist。
- **落地实施**：第 13 章代码 + 第 03 章模板，能拼出一个最小可用版本。

准备好了就从 [第 00 章](/intro/) 开始。如果你正在救火，直接去 [第 12 章踩坑清单](/pitfalls/)。
